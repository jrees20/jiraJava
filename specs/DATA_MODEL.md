# Data Model Specification

## Core Domain Models

### OvernightSummary
Primary output model — what the user sees first.

```typescript
interface OvernightSummary {
  id: string                    // UUID
  userId: string                // Who is this summary for?
  generatedAt: Date             // When was it generated
  generatedFromData: Date       // What time period (e.g., last 24h)
  
  // Aggregated counts
  metrics: {
    jiraItemsRequiringAction: number
    escalationsAssigned: number
    itemsResolved: number
    itemsClosed: number
    criticalEmails: number
    agingEmails: number
    meetingConflicts: number
    unacceptedMeetings: number
  }
  
  // AI-generated insights
  biggestRisk: {
    title: string               // e.g., "ANB Sprint 1 integration testing is blocked"
    source: 'JIRA' | 'EMAIL' | 'CALENDAR'
    sourceId: string            // Reference to the item (issue key, email id, etc.)
    severity: 'CRITICAL' | 'HIGH' | 'MEDIUM'
  }
  
  // Recommended actions ranked
  recommendedActions: RecommendedAction[]
  
  // Raw items grouped by type
  jiraItems: JiraItem[]
  emailItems: EmailItem[]
  calendarItems: CalendarItem[]
  
  // Metadata
  attentionScore: number        // 0-100, composite metric
  sourcesQueried: ('JIRA' | 'OUTLOOK' | 'TEAMS')[]
  generationTimeMs: number      // How long did aggregation take?
}

interface RecommendedAction {
  order: number                 // 1, 2, 3...
  description: string           // "Review DAIS-123"
  sourceType: 'JIRA' | 'EMAIL' | 'CALENDAR'
  sourceId: string              // Issue key, email id, meeting id
  actionType: 'REVIEW' | 'RESPOND' | 'ACCEPT' | 'RESOLVE' | 'ESCALATE'
  estimatedTime: number         // Minutes
}
```

### JiraItem
Issue that changed overnight and is relevant to user.

```typescript
interface JiraItem {
  id: string                    // UUID (internal)
  issueKey: string              // DAIS-123
  summary: string
  priority: 'BLOCKER' | 'P1' | 'P2' | 'P3' | 'P4' | 'P5'
  projectKey: string
  projectName: string
  
  // Status tracking
  currentStatus: string         // "In Progress"
  previousStatus: string | null // "Open"
  statusChangedAt: Date
  
  // Activity
  changeType: 'NEW' | 'STATUS_CHANGE' | 'BLOCKER' | 'ESCALATION' | 
              'SEVERITY_1' | 'SEVERITY_2' | 'RESOLVED' | 'CLOSED' | 
              'MENTIONED' | 'ASSIGNED' | 'COMMENTED'
  
  changedBy: {
    id: string
    name: string
    avatarUrl: string
  }
  
  // Relationships to user
  relevanceReason: 'ASSIGNEE' | 'REPORTER' | 'WATCHER' | 'MENTIONED' | 'TAGGED' | 'APPROVER'
  
  // Metadata
  url: string                   // Link to Jira
  updatedAt: Date
  blockedBy?: string            // If blocker, which issue blocks this
  blocks?: string[]             // Issues this blocks
}
```

## Database Schema (PostgreSQL)

### Users Table
```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email VARCHAR(255) UNIQUE NOT NULL,
  name VARCHAR(255),
  
  -- Preferences
  timezone VARCHAR(50) DEFAULT 'UTC',
  business_hours_start SMALLINT DEFAULT 8,      -- 8 AM
  business_hours_end SMALLINT DEFAULT 18,        -- 6 PM
  
  -- Integrations
  jira_user_id VARCHAR(255),
  outlook_user_id VARCHAR(255),
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### OvernightSummaries Table
```sql
CREATE TABLE overnight_summaries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  
  generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  generated_from_date TIMESTAMP,
  
  attention_score SMALLINT,
  biggest_risk_json JSONB,
  metrics_json JSONB,
  
  generation_time_ms INTEGER,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  UNIQUE(user_id, DATE(generated_from_date))
);

CREATE INDEX idx_overnight_summaries_user_date 
  ON overnight_summaries(user_id, generated_from_date DESC);
```

### CachedItems Table (for 5-min TTL)
```sql
CREATE TABLE cached_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  
  source_type VARCHAR(50),     -- 'JIRA', 'OUTLOOK', 'CALENDAR'
  source_id VARCHAR(255),      -- Issue key, email ID, etc.
  
  item_data JSONB NOT NULL,
  
  cached_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP,        -- 5 minutes from cached_at
  
  UNIQUE(user_id, source_type, source_id)
);

CREATE INDEX idx_cached_items_expires 
  ON cached_items(expires_at) 
  WHERE expires_at > CURRENT_TIMESTAMP;
```

### Integration Tokens Table
```sql
CREATE TABLE integration_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  
  provider VARCHAR(50) NOT NULL, -- 'JIRA', 'OUTLOOK', 'TEAMS'
  
  access_token TEXT NOT NULL,
  refresh_token TEXT,
  expires_at TIMESTAMP,
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  
  UNIQUE(user_id, provider)
);
```

## Notes for Team

1. **OvernightSummary** is the main aggregate — it pulls from JiraItem, EmailItem, CalendarItem
2. **Caching:** All items should cache with 5-minute TTL to avoid API rate limits
3. **User Timezone:** Business hours are user-specific (see Users table)
4. **Attention Score:** Composite metric (TBD algorithm) — higher = more urgent
5. **JSON Flexibility:** Use JSONB columns for extensible metadata
